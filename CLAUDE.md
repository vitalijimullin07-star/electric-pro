# Заметки для разработки Plata

- Интерфейс, тексты и комментарии на русском, в предложениях обычный регистр.
- Стек: TypeScript (strict), Vite, React 19, zustand + immer, vitest. Без других фреймворков; для симуляции AVR подключена библиотека avr8js (MIT).
- Все размеры в модели — миллиметры, ось Y вниз, углы в градусах (положительный — против часовой на экране).
- Проект (`src/core/model/types.ts`) — простой сериализуемый объект. Изменения только через `commit` в store (immer) либо функциями `src/core/model/edit.ts` на свежем объекте. Кеши связности, DRC и геометрии привязаны к объекту проекта через WeakMap: после правок «на месте» (в тестах) делайте `structuredClone`.
- Ядро (`src/core`) не знает про React и DOM: его можно запускать в воркере и в Node.
- Слои названы как в KiCad (`F.Cu`, `B.Cu`, `F.Silk`, `Edge.Cuts`…), см. `src/core/model/layers.ts`.
- Корпуса в библиотеке (`src/core/library`) — параметрические генераторы. Новый корпус: функция в `generators/*.ts`, добавить в `all*()`, размеры из даташита, `verified: true` только если сверено. Тест `tests/library.test.ts` проверит площадки, габарит и уникальность.
- После изменений: `npm run check` (типы + тесты). Если трогали автотрассировку или связность — `npm test -- tests/router.test.ts` обязательно (плата пылесоса должна разводиться без ошибок).
- Заливка полигонов — `src/core/model/zone-fill.ts` (поле расстояний на сетке + marching squares), считается внутри `computeConnectivity` и достаётся через `getZoneFills`. Во время перетаскивания DRC и заливка берутся из состояния до его начала (`stableProject` в store) — не вызывайте `runDrc(s.project)` из компонентов, которые перерисовываются на каждом кадре.
- Качество графики — `src/render/quality.ts`. В `canvas-renderer.ts` не используйте `shadowBlur` на крупных путях (плата, контур): на телефоне это десятки миллисекунд на кадр — ореол рисуйте широкой полупрозрачной обводкой. Замер кадра: `window.__plata.bench(уровень, кадров, dpr)` при `?qa=1`.
- Симуляция — `src/core/sim` (ядро: контроллер `mcu.ts`, цепи и уровни `circuit.ts`, детали `devices.ts`, дисплеи `hd44780.ts`/`ssd1306.ts`), исполнитель в редакторе — `src/editor/sim-runtime.ts`, панель — `src/ui/panels/SimPanel.tsx`. Тестовые прошивки — C в `tests/fixtures/fw`, собираются `sh tests/fixtures/fw/build.sh` (нужен avr-gcc), готовые .hex лежат рядом. Новая деталь для симуляции: ветка в `buildDevices` (по корпусу и именам выводов) + тест в `tests/sim.test.ts`.
- Аналоговый расчёт — `src/core/sim/analog`: `solver.ts` (разреженное LU по Марковицу, комплексный Гаусс для АЧХ), `engine.ts` (узловой метод, земля — узел −1, θ-метод 0,55, после фронта шаг неявный; разложения кешируются по коду состояний кусочно-линейных элементов; конденсаторы и дроссели считаются общим циклом), `elements.ts` (диод, MOSFET, BJT, ОУ, TL431, стабилизатор, 555, вывод контроллера, двигатель), `parts.ts` (модели по названию), `coil.ts` (катушка DD), `build.ts` (`AnalogSim`: цепь → узел, деталь → модели, `sync()` досчитывает до такта контроллера, осциллограф, `acSweep`). Включается `Simulation(..., { analog: true, analogDt })`; тогда `Circuit.analogNet` и `Avr.beforeAdc` берут напряжения из расчёта, логика уровней остаётся в `Circuit`. Состояние, поменянное снаружи (`Switch.closed`, `McuPinEl.mode`), — только с `engine.kick()`. «0/1» на выходе контроллера не меняют матрицу (питание — в правой части), поэтому ШИМ не вызывает разложений; выводы без аналоговой нагрузки не моделируются. Новая деталь: ветка в `AnalogSim.buildPart` + тест в `tests/analog.test.ts`. Интерфейс — вкладка «Цепь» (`AnalogPanel.tsx`), ток по дорожкам — `src/render/current-flow.ts` (дерево цепи, оценка).
- Симуляция без контроллера: `findMcu` не нашёл контроллер → `NullMcu` (`null-mcu.ts`, 1 МГц, очередь событий), аналоговый расчёт включён всегда, детали — только из расчёта (`analogDevices` в `analog/devices.ts`). Вид детали угадывает `detectKind` (`analog/kinds.ts`: обозначение, номинал, корпус; сначала номинал, теги корпуса ненадёжны), вручную — `Component.sim.model`/`params` (окно свойств, `SimModelSection.tsx`); строит `buildPart` (`analog/models.ts`). Земля — цепь GND, иначе минус батареи/источника; питание по имени (VCC, +5V) подаётся, только если цепь не запитана через проводящие детали (`energized`). Сеть — цепи L и N; генераторы — `project.sim.sources`. Среднее для яркости и мощности — окно 20 мс (`average`), чтение ничего не сбрасывает. Новая деталь: вид в `KIND_INFO` + ветка в `detectKind` и `buildPart` + тест в `tests/sim-models.test.ts`. Примеры — `src/core/examples/sim-circuits.ts` (`Builder`, в «Новый проект → Примеры»), тесты — `tests/sim-nomcu.test.ts`. Карточка параметров на холсте — `SimTuner.tsx` (`simRuntime.tune`, `openTune`/`closeTune`): тройной щелчок или удержание во время симуляции (`checkDoubleTap`/`startLongPress` в `interaction.ts`, `maybeDouble` в `sch.ts`; двойной щелчок в это время откладывается на 400 мс), ползунок с вводом и шагами E24 — `KnobRow` в `AnalogPanel.tsx`, детали на цепи — `AnalogSim.partsOnNet`.
- ESP32 — класс `Esp32` в `esp32.ts`: исполняет ядро прошивки, собранное в WebAssembly (`Firmware.wasm`, base64), обвязка — импорты `env` (выводы, АЦП по напряжению цепи, I²C через `I2cNetwork`, тон, лог, настройки). Такт — микросекунда, `vac_tick` каждые 100 мкс, прерывания откладываются до выхода из вызова wasm. Компиляция асинхронная: `Simulation.create`; в тестах — `createSync`.
- Контроллер пылесоса: прошивка `firmware/vacuum-esp32` (ядро `vac_core.c`/`vac_link.c`/`vac_drv.c` → HAL `vac_hal.h`; ESP32 — `hal_esp32.cpp`, симуляция — `sim_wasm.c`). После правки ядра: `sh firmware/vacuum-esp32/build-sim.sh` (clang → `vacuum-esp32.wasm`, закоммитить), для ESP32 — `/root/tools/arduino-cli compile --fqbn esp32:esp32:esp32 --output-dir build firmware/vacuum-esp32`. Выводы в `vac_core.h` и в `parts.ts` (A1) должны совпадать. Пульт — `firmware/vacuum-panel` (ESP32-S3 с экраном 800×480, общий для v1 и «S3»: `panel_ui.c` экраны и протокол v1, `panel_s3.c` — «S3», `gfx.c` графика RGB565, `fonts.c` из `tools/make_fonts.py`; `vacuum-panel.ino` + `hal_s3.cpp` — экран esp_lcd, GT911, UART; выводы платы не проверены на железе). После правки: `sh firmware/vacuum-panel/build-sim.sh` (→ `vacuum-panel.wasm`, закоммитить), для S3 — `arduino-cli compile --fqbn esp32:esp32:esp32s3:PSRAM=opi --output-dir build firmware/vacuum-panel`. Протокол между ними — строки UART, описан в `panel_ui.h`; в проекте прошивка пульта — `firmware.modules.HG1`, в симуляции — `PanelS3` (`panel-s3.ts`), байты — через `Esp32.uartWrite`/`onUart`. Установка — `vacuum.ts` (детали по меткам корпуса, датчики по полю «Где стоит»). Проект — `src/core/examples/vacuum-esp32` (`build.ts`: плата, зоны правил, переходные и шина земли, `routeVacuumEsp32`; `notes.ts`), файлы `import/vacuum-esp32*` и `vacuum-panel-proshivka.bin` пересоздаёт `VAC_WRITE=1 npx vitest run tests/vacuum-esp32.test.ts` (разводка ~30 с; перед этим соберите обе прошивки arduino-cli). Полноэкранная симуляция — `src/ui/SimFullscreen.tsx` (пульт с экраном — `PultFront`, экран с касаниями — `PanelScreen` в `SimPanel.tsx`), история для графиков — `simRuntime.history`.
- Автотрассировка (`src/core/router/autoroute.ts`): сетка задаётся (`grid`), шаги прямо и под 45° (`diagonal`; диагональ занимает угол квадрата из четырёх клеток — `cocc`, на мелкой сетке и боковые клетки), A* с метками поколений (массивы не очищаются на каждую связь), слегка «жадный» (`greed`, 1 — точный). Переходное занимает клетки ближе радиус + зазор + полуширина, переходные между собой — по карте `viaAt`; прыжки из клетки раскрываются один раз за поиск. `congestionGrowth` — рост цены спора (по умолчанию 1,7), `layerCost` — цена слоя, `order`/`seed` — порядок цепей для разных вариантов, `noisy`/`sensitive` — поле помех (чувствительным дороже рядом с помехоопасными). После согласования — чистовой проход (`polish`): каждая цепь заново без истории споров, остаётся, если меньше прыжков или короче. В режиме `keepExisting` деревом цепи считается связанная с первой площадкой медь, включая заливку. Области правил могут действовать на одном слое (`RuleArea.layers`). Свои площадки цепи исключены из запретов своего класса (оптрон поперёк зазора 6 мм).
- Авторасстановка — `src/core/place/autoplace.ts` (отжиг: длина связей, пересечения связей и «стены» — ряды выводов, между которыми не пройти дорожке, перекрытия, край, зоны правил, зазор до сети, помехи, разъёмы к краю, развязка; закреплённые и без подключённых выводов не двигаются). Роли цепей — `src/core/model/net-roles.ts` (`Net.role` или угадывание). Перебор вариантов «расстановка + трассировка» — `src/core/router/variants.ts` (`planVariant`, `runVariant`, `scoreOf`, `applyVariant`), пул воркеров по числу ядер — `startVariantSearch` в `client.ts` (без воркеров — по очереди в основном потоке), окно — `src/ui/dialogs/AutoDesignDialog.tsx`. Плата пылесоса ESP32 разводится без диагоналей и точным поиском (`routeVacuumEsp32`, расстановка подогнана под прямые углы).
- Самодельная плата без металлизации: у сквозной площадки `PadDef.layer` — медь только с этой стороны (`padCopperLayers`), трассировщик подводит дорожку к выводу только по ней, с другой стороны вокруг голого отверстия — запрет (без диагоналей — ровно зазор, с диагоналями — с запасом на G/√2), DRC — ошибка «Отверстие … касается», заливка обходит отверстие. Сверху тогда — только дорожки между переходными; шаг сетки 1,27 пропускает одну дорожку 0,6 (зазор 0,4) между отверстиями с шагом 2,54, если ширины всех разводимых классов не больше 0,7.
- Трассировщик: «ореол» у площадок и сохранённой меди — по классам разводимых сейчас цепей (`maxHw`/`maxClr`), медь других классов держит свой зазор (`clrTo`), особые зазоры (6 мм от сети) — запреты `forbid` от меди любого класса (и от сохранённых дорожек); свои площадки из запретов исключаются после всех запретов. Площадки перемычек (оба конца) заносятся в карту переходных `viaAt`. `deadline` — согласованию ¾ срока, последняя попытка — хотя бы круг, чистовой проход после срока не делается. `autoGrid(p, nets)` — по классам этих цепей, шаги кратны шагу выводов (0,4233 = 1,27/3, 0,635, 0,8467 = 2,54/3, 1,27…).
- Перебор вариантов: разводка по этапам (`routeStages`: классы с зазором ≥ 2× наименьшего — первыми на своей крупной сетке, остальное — на мелкой, `keepExisting`); на платах с выводами шагом ≤ 1,3 мм — «тонко, потом шире» (`job.thin`: минимум правил на мелкой сетке, затем `fitTrackWidthsSafe` до ширины класса и тока); диагонали — только на сетке ≥ 0,8 мм; на двусторонней плате связь без пути остаётся воздушной линией (провод через SMD-площадку замкнул бы слои); у каждого варианта срок (`job.deadline` — срок поиска, первый вариант при поиске от 30 с — за половину); с «Расставить» первый вариант — детали как стоят. Окно: на телефоне при поиске варианты — сверху, прогресс — в подвале.
- Распутывание паутины — `src/core/model/untangle.ts`: каждая цепь — дерево связей между островками, связи заменяются так, чтобы меньше пересекаться между собой и со «стенами» (соседние выводы детали, между которыми не пройти дорожке; свои стены детали тоже считаются). По графу пересечений — оценка прыжков: `minJumps` (жадное покрытие, одна сторона) и `minViaPairs` (раскраска в два слоя); это оценка по прямым линиям, не нижняя граница. `untangledRatsnest(p)` кешируется по объекту проекта; редактор считает её с задержкой после правок (`CanvasView`), рисует через `peekUntangled` и не во время перетаскивания. Расстановка после отжига доводит места по распутанным деревьям (`untangle: false` — выключить). План для трассировщика — `routePlan` → `RouteOptions.plan`/`planHop` (порядок выводов, дешевле перемычка на запланированных связях, предпочтительный слой); сам по себе план в среднем не лучше, поэтому это лишь одна из стратегий перебора (каждый шестой вариант). Перебор не начинает вариант, который по времени прошлых такого же вида не успеет к сроку, и не обрывает поиск, пока нет ни одного готового варианта.
- Ширина по току — `src/core/model/currents.ts`: ток выводов по знаниям о детали (стабилизаторы и преобразователи по названию или току в описании, блоки HLK, трансформатор по ВА и «230/9 В», предохранитель по номиналу, нагрузки по ваттам — только по номиналу, корпусу или обозначению M/YA/EK…, не по свободному описанию; разъёмы тока не задают), ток цепи — больший из самого сильноточного вывода и суммы потребителей; выносные детали — если их ток может пройти по плате. `Net.current` — вручную. Ширина — IPC-2221 (`rules.copperThickness`, `tempRise`, предел `maxAutoWidth`), `netWidth(p, net)`. Подгонка — `track-fit.ts` (`fitTrackWidthsSafe`: куски по 0,5 мм, ширина до зазора, сужения у выводов, откат цепей, если расширение рвёт чужую заливку); только цепи, которым по току нужно шире класса. Галочка «авто» у ширины (`routeWidth: 'auto'`): новая дорожка кладётся по классу и расширяется подгонкой; «Трассировка → Ширина дорожек по токам»; в переборе — `use.current`; DRC — предупреждение `width` (короткие сужения у своих выводов не в счёт).
- Пылесос «S3» (v2, схема v3): проект — `src/core/examples/vacuum-s3` (`parts.ts` детали и места, `build.ts` плата, зоны, отводы земли у USB-C и PCA9555, `routeVacuumS3` по этапам: ток турбин, сеть, выпрямитель 0,4 мм на сетке 0,635 (шаг сетки ≥ ширина + зазор, иначе соседние клетки разных цепей нарушают зазор), USB и земля на сетке 0,25, логика 0,2 мм на 0,4233 и расширение `fitTrackWidthsSafe`; `notes.ts`). Выводы TSSOP (0,65 мм) на сетке 0,4233 недоступны — только SOIC/шаг ≥ 0,95. Эта плата (SMD, клапаны на магнитах 12 В, `build.ts`/`dip.ts`/`notes.ts`, файлы `import/vacuum-s3.plata.json`, `-perechen`, `.txt`, `vacuum-s3-dip*`) — архив: внутри файлов прошивка 4.0 (исходники — коммит a8c9be7), заново не пишутся. Прошивка — `firmware/vacuum-s3` (то же ядро vac_*, что у v1, другие выводы), 5.0 — под плату на модулях (ниже); после правки: `sh firmware/vacuum-s3/build-sim.sh` и `arduino-cli compile --fqbn esp32:esp32:esp32s3:CDCOnBoot=cdc,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi --output-dir firmware/vacuum-s3/build firmware/vacuum-s3`. Сообщения ядра — UTF-8 (кириллица — 2 байта на букву): буферы строк считать в байтах. В ядре: серии ударов обоими клапанами 25–80 мс (режимы `PRESET_DEF`, «Авто» — длина по фронту обратного перепада, интервал по росту R, число — пока удар снижает R), проверка клапанов по одному (`diag_req`: первая серия и раз в 60 ударов; эти удары не в счёт серии — `diag_n`), мощная очистка при закрытом шланге, паспорт двух фильтров А/Б, сила удара (фильтр клапанов), розетка (автозапуск, выбег, удары в конце, перегрузка с выбором на экране, пусковой ток не в счёт), Bluetooth до 4 устройств (пульт и метки), настройки — две копии (`hal_settings_load2/save2`, слоты), Wi-Fi для телефона (`hal_wifi`, пароль из `hal_rand32`), обновление с телефона (метки «VACFW:S3-CTRL:»/«VACFW:PANEL:», откат, пульт — по UART строками U). Экран — та же `firmware/vacuum-panel` (`panel_main.c` выбирает `panel_ui.c` или `panel_s3.c` по полю e1 в строке «S»; кнопки у экрана — «E k=N»; QR-код — `qr.c`; строки контроллера S/F/C/J/W описаны в `panel_ui.h`). Пульт Bluetooth — `firmware/vacuum-remote` (ESP32-C3, `--fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc`), метка на инструмент — `firmware/vacuum-tag` (ESP32-C3 + LIS3DH, та же fqbn); в симуляции — `ble-remote.ts` (`BleRemote`, `BleTag`, подпись SipHash-2-4 со счётчиком). В модели установки (`vacuum.ts`) — пневматика из двух объёмов (бак по полю «Объём» электрода, камера по полю «Камера» датчика перепада), клапаны на магнитах (метка magnet-valve), розетка (tool-outlet) с реле, ТТ, реле (метка relay, катушка через ключ), бак с электродами и поплавком (water-electrode, float-switch); PCA9555 и SDP811 (0x26) — в `devices.ts`; ток шунта — источники тока в `circuit.ts`. Вариант на выводных деталях для ЛУТ — `dip.ts` (`s3DipParts`: замены корпусов, DevKitC-1 вместо модуля, MP1584 вместо AP63205, PCA9555 на переходнике DIP-24), `buildVacuumS3(fw, panel, { dip: true })` — без дорожек, детали рядами (сеть отдельно). Плата пульта — `pult.ts` (рамка вокруг экрана 7″: кнопки 1–6 напротив зон подписей 26 + 104·i из 480, энкодер внизу, разъёмы на обратной стороне; `PULT_SCREEN` — размер стекла, сверить; `routePult` — сетка 0,8467 без диагоналей). Плата под купленные модули (ЛУТ, без металлизации) — `mod.ts` (`buildVacuumS3Mod`, `routeVacuumS3Mod`, памятка `vacuumS3ModNotes`, выводы `MOD_PINS`): DevKitC-1 N16R8 (IO35–IO37 — PSRAM, не трогать), PCA9555 на платке 800 mil, мост KBP (шаг 3,81, «+ ~ ~ −»), ключи SS8050 к модулям реле 30 А и SSR G3MB (включение низким уровнем), ШИМ к МР248, SCT-013 с выходом 1 В, MPX5100DP, экран ILI9488 по SPI (X2) и пульт (X1); все выводы паяются снизу; разводка — сеть на 2,54, остальное одним согласованием на 1,27 с перебором порядков; выносные по желанию — пульт и метка Bluetooth (HG2, HG3). Прошивка 5.0 (выводы — `vac_core.h` = `MOD_PINS`): реле — «1» на выводе (ключ замыкает IN модуля на землю), турбины — `hal_pwm` 20 кГц к МР248 (скважность = мощность), клапаны — SSR: вход включается в `vac_tick` сразу, а `vlv_off_at` — за 1 мс до нуля после целого числа полупериодов (`vlv_ms`), ТТ — 1 В на 20/30 А (`CT_MV_PER_A`), 5.1 — тарельчатые клапаны (`vlv_kind` = `VK_PLATE`, «set valves plate|pulse»; настройки версии 4 переносятся как импульсные): удерживающий магнит 230 В через SSR под током, пока есть разрежение (`vlv_arm`, турбины пускаются через 150 мс после магнитов), удар — снять ток (выводы клапанов пишет только `vac_tick`), турбины на время удара — на `dip` % слабее (70 по умолчанию: по 3D-расчёту обратный поток в 1,25–1,5 раза больше), `plate_watch`: провал разрежения и перепада без удара или дребезг — сброс турбин на 0,6 с, пока пружины закроют (`VE_NOCLOSE` / `VE_HOLD`); модель — `holdPlate` в `vacuum.ts` (метка plate-valve: сила магнита по зазору, пружины, площадь 52,8 см², проход как Ø54), очистка по порогу перепада (`dp_on`, Па при расходе уставки: R = Δp·100/sp², `r_of_dp`; 0 — «авто» по росту R; экран «Фильтр · ещё», «set dp N»), слабый удар (обратного перепада почти нет — широкий шланг) — `F_WEAK` (бит 31) с подсказкой про мощную очистку, PCA9555: P12 сброс экрана и P13 светодиод — выходы (`exp_init`/`exp_write`), P14 — касание (`K_TOUCH`). Экран ILI9488 + XPT2046 — прямо на контроллере (`lcd_s3.cpp`, задача на ядре 0): интерфейс пульта (копия `firmware/vacuum-panel` в `firmware/vacuum-s3/src/panel` — `sh firmware/vacuum-s3/sync-panel.sh` после правки пульта, тест сверяет; в копии `PANEL_IN_CTRL` — без метки «VACFW:PANEL:») рисует 800×480 в PSRAM, уменьшение 5→3 до 480×288, на экран — изменившиеся полосы RGB666; строки контроллера — из `hal_uart_write` (`lcd_rx_put`), команды — кольцом в `loop()` (`lcd_poll_tx`); команды «lcd cal|flip|rgb|off|on», калибровка касания в prefs. В симуляции: экран HG1 — модуль `firmware.modules.HG1` (тот же `PanelS3`), `Esp32.pwmDuty`; в `vacuum.ts` — модули реле (relay-module: катушка DC+ — IN), МР248 (triac-dimmer: угол — по доле мощности из скважности, `dimmerAngle`), SSR (ssr-module: канал — `Triac.ssr`, открывается только в нуле), импульсные клапаны 230 В через SSR — в той же динамике камеры и бака (`MagValve.pulse`, `pulsePlate`), ТТ с выходом 1 В (sct013-v: источник напряжения на S1 относительно S2). Файлы `import/vacuum-s3-mod*`, .bin (`vacuum-s3-proshivka.bin` целиком с адреса 0, `*-app.bin` для телефона, у пульта 7″ — `vacuum-panel-*`) пересоздаёт `VAC_WRITE=1 npx vitest run tests/vacuum-s3.test.ts -t "на модулях"` (сначала arduino-cli обеих прошивок); медь платы берётся из её файла (`withRoutingOf` — её уже печатали), развести заново и пересоздать PDF и плату пульта — `VAC_REROUTE=1`.
- ATmega32A — тот же класс `Avr` в `mcu.ts` с регистрами ATmega32 (таймеры 0 и 2 с одним TCCR раскладываются на пару регистров avr8js, общие TIFR/TIMSK, разностный АЦП, заплатка старта ШИМ с коррекцией фазы). Частота — по кварцу у XTAL1/XTAL2 или `project.firmware.freq`. Цепи (`circuit.ts`): делители по номиналам резисторов, «жёсткие» цепи (шунт до 10 Ом на питание) держат выводы сильнее выхода, дроссели — перемычки, диоды и кнопки между сигналами решаются вместе (`solveLinks`), транзисторы — ключи в `devices.ts`. Катушка металлоискателя — `metal-detector.ts`.
- Выносные детали (`Component.offBoard`): дисплей, кнопки на корпусе, датчики. `getWorld` их пропускает, поэтому их нет на плате, в DRC, Gerber и расстановке; на схеме, в перечне и в симуляции они есть.
- Импорт Sprint Layout — `src/core/io/sprint-layout.ts` (единицы v5 — 0,01 мм, v6 — 0,0001 мм, ось Y вверх). Проект «Квазар» собирается из `tests/fixtures/quasar` функцией `src/core/examples/quasar/build.ts` (таблица деталей — `parts.ts`); файлы в `import/quasar-*` пересоздаёт `QUASAR_WRITE=1 npx vitest run tests/quasar.test.ts`.
